# Team Management Specification (Phase 9)

## Overview
This document defines the complete business rules, permissions, edge cases, and module breakdown for the Team Management feature of NEXUS 2026. This is the core operational heart of the application.

---

## 1. Team Creation & Identifiers

- **Creator:** Only a logged-in, verified user with an initialized profile can create a team.
- **Team Types:**
  - `Solo`: Exactly 1 Member (The Leader).
  - `Team`: Minimum 2 Members, Maximum 3 Members (including the Leader).
- **Identifiers Generated by System:**
  - **Team ID:** E.g., `HIET/TM/1001` (Auto-incrementing, public identifier).
  - **Join Code:** E.g., `A7K9P2` (6-character alphanumeric, private code to prevent spam requests).

---

## 2. Security Rule (Strict 1:1 Mapping)

> [!CAUTION]
> **1 User = 1 Active Team**
> - A user can only be part of **one active team** at any given time.
> - If a user is already in a team (as a leader or member), they **cannot** create a new team or join another team.
> - A user must leave their current team or wait for the team to be deleted before they can join/create a new one.

---

## 3. Permissions Model

### Leader Permissions
**Can Do:**
- Edit Team details (Name, Type).
- Invite Members via Email/User ID.
- Accept or Reject incoming join requests.
- Remove Members from the team.
- Edit Conference Registration details.
- Upload Research Paper and Save Drafts.
- Final Submit the team's application.

**Cannot Do:**
- Edit the team, registration, or paper **after** Admin Approval or Final Submit (unless unlocked by Admin).

### Member Permissions
**Can Do:**
- View Team details.
- View Registration details.
- View Research Paper draft.
- Accept or Reject an invite from a Leader.
- Leave the team (before Final Submit).

**Cannot Do:**
- Edit Team details.
- Invite or Remove Members.
- Upload Research Papers.
- Submit the Final Registration.

## 4. Join Request Flow

### Flow A: Leader Invites Member
```ascii
[Leader] --> (Sends Invite via Email/ID) --> [System]
                                                |
                                                v
[System] --> (Sends Email + Dashboard Alert) --> [Member]
                                                |
                                                v
[Leader] <-- (System adds member to team) <--- [Accepts]
```

### Flow B: Member Requests to Join
```ascii
[Member] --> (Enters Team ID: HIET/TM/1001) 
             (Enters Join Code: A7K9P2) --> [System]
                                               |
                                               v
[System] --> (Verifies Code, Sends Alert) --> [Leader]
                                               |
                                               v
[Member] <-- (System adds member to team) <-- [Accepts]
```
*Note: The Join Code prevents spam. If the code is incorrect, the request is immediately blocked by the system.*

## 5. Team Status Lifecycle

1. **Draft:** Team created, members joining, paper not submitted.
2. **Complete:** Team capacity met (if applicable), all registration fields filled.
3. **Submitted:** Leader clicked Final Submit. Locked for editing.
4. **Under Review:** Admin has started reviewing the submission.
5. **Needs Correction:** Admin returned the submission for fixes (Unlocks editing temporarily).
6. **Approved:** Submission fully accepted.
7. **Rejected:** Submission denied.
8. **Locked:** Global freeze (e.g., deadline passed).

---

## 6. Team Capacity & Submission Rules

- **Maximum Capacity:** Cannot exceed 3 Members (including Leader).
- **Minimum Capacity (Team Type):** Cannot submit if members < 2.
- **Empty Team:** Cannot submit if 0 Members (Impossible as Leader counts as 1).
- **Post-Submission Freeze:** Cannot invite, remove, or leave after the team status shifts to `Submitted` or beyond.

---

## 7. Edge Cases & Handling

- **Leader Leaves:** The Leader cannot leave. The Leader must transfer ownership (if implemented) or Delete the team.
- **Member Leaves:** Reduces team count. If team type is 'Team' and count drops below 2, status reverts to `Draft` and cannot be submitted.
- **Invite Expires:** Invites auto-expire after 7 days.
- **Duplicate Request:** System blocks if an active request already exists between the user and the team.
- **Already in Another Team:** System blocks invite/request generation if the target user is already in an active team.
- **Deleted Team:** Requests to a deleted team return "Team not found".
- **Rejected Request:** User cannot request again for 24 hours (Rate limited).

## 8. Dashboard Structure

### Leader Dashboard
`Overview` ➔ `Team Management` ➔ `Members` ➔ `Registration Form` ➔ `Paper Upload` ➔ `Notifications` ➔ `Profile` ➔ `Settings`

### Member Dashboard
`Overview` ➔ `My Team (Read Only)` ➔ `Paper (Read Only)` ➔ `Notifications` ➔ `Profile`

---

## 9. Notifications & Email Flow

- **Leader Alerts:** Invite Accepted, Member Joined, Member Left, Submission Success, Admin Approval.
- **Member Alerts:** Invite Received, Invite Accepted, Invite Rejected, Submission Completed by Leader.
- **Email Triggers:** Sent concurrently with in-app notifications for: Invitation, Acceptance, Rejection, Submission, Approval.

---

## 10. Audit Log & Soft Deletes

- **Audit Log:** Every CRUD action on the team logs: `Time`, `User ID`, `IP Address`, `Device/Agent`.
- **Soft Delete:** Teams are NEVER permanently deleted from the database. Deleting a team sets `isDeleted: true`. This preserves historical data and prevents DB integrity issues.

---

## 11. Implementation Modules

To ensure a bug-free and scalable architecture, Phase 9 will be implemented sequentially in 3 distinct modules:

### Module 1: Core Architecture
- Create Team DB Schema.
- Implement Team ID Generator (`HIET/TM/XXXX`).
- Implement Join Code Generator.
- Handle Team Type logic (Solo vs Team).
- Scaffold the Team Dashboard UI.

### Module 2: The Networking Layer
- Build Invite Members API.
- Build Join Request API (using Join Code).
- Implement Accept/Reject logic.
- Integrate Notification System.

### Module 3: Security & Finalization
- Build Remove Member & Leave Team flows.
- Enforce Lock Rules (Freeze on Submit).
- Handle Team Status state machine.
- Final UI Polish.
